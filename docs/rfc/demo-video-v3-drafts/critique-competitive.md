# Critique: Competitive Landscape

A skeptical peer review of the v3 demo bundle (`rfc.md`, `script.md`, `linkedin.md`) against the tools a LinkedIn viewer is realistically using today. Verdict up front: the script differentiates well against orchestration frameworks and IDE-coupled tools, but it leaks badly against the most common viewer mental model — `tmux` + vanilla Claude Code. If a viewer's first thought is "I already have a 4-pane tmux on my second monitor," nothing in the first 35 seconds dislodges that.

### Closest 3 competitors a LinkedIn viewer probably uses

1. **`tmux` (or `zellij`) split panes with vanilla Claude Code / Codex CLI.** The free, zero-install baseline. Kookr adds (a) automatic anomaly detection — Claude waiting on a permission prompt surfaces without the human watching the pane, (b) AI-drafted replies, (c) GitHub PR/CI awareness fused into the same queue, (d) cost ledger, (e) per-project budgets. Is this visible in <30s? **Partially.** Act 0's caption "One needs you. Which one?" implies routing, but the visual is still five terminals in a grid — exactly what a tmux user already sees. The "pulsing yellow indicator" needs a visible explanation that tmux does not do that.

2. **Cursor / Windsurf / Zed AI (IDE-coupled, single-agent).** Inline chat-with-editor; no multi-agent supervision, no parallel session graph. Kookr is orthogonal — it supervises N CLI agents while you do other work. Is this visible in <30s? **Yes, by absence.** The dashboard chrome and five-row queue read as obviously not-an-IDE. Low risk of confusion.

3. **`crewAI` / `autogen` / `OpenDevin` (orchestration frameworks and autonomous agents).** These define agent topologies and run them headlessly; they do not put a human in the supervision loop. Kookr is the opposite axis: humans-in-the-loop for agents you launched manually. Is this visible in <30s? **No, and the script does not try.** The word "supervise" never appears in any caption; "attention router" only lands in the LinkedIn post body, not the video. A `crewAI` user might shrug and think "I have agents.json, why do I need a UI?"

### Where the script gets the comparison RIGHT

- **Act 3 (cross-project triage) is the strongest differentiator.** Two findings on two different agents on two different projects on two different runtimes, resolved in one continuous gesture. tmux cannot do this. `aider` cannot do this. `crewAI` does not even try. The Codex badge on Finding A's header is the load-bearing pixel of the whole video.
- **Act 4 (GitHub PR + CI lands in the same queue) is a clean kill against IDE-coupled tools** (Cursor, Continue, Zed). They watch your buffer; Kookr watches the agent's external loop. The toast "CI failed on PR #142" is something no IDE assistant ships.
- **Act 5 (cost ledger updates $1.47 → $1.89) differentiates against every framework** that does not surface spend per agent. It is also the "I could justify this to my manager" beat the script correctly names.
- **The LinkedIn body's "ranked findings, not toast spam"** is a sharp anti-Cursor-notifications jab. Keep it.

### Where the script gets the comparison WRONG

- **Act 0 looks like tmux in screenshot form.** Five rows of terminal output, one with a yellow indicator, is visually identical to a tmux pane grid with one pane scrolled to a permission prompt. The caption "5 AI agents working. One needs you. Which one?" describes the problem tmux users already have — it does not say Kookr *detected* the needy one. A tmux user reads this as "yes, that is my Tuesday." Fix: the caption must name the *automation*, not the symptom.
- **Act 1 leans on filter chips, which is also a tmux-window feature** (`prefix + s` lists sessions). The 0:17 caption "Claude Code + Codex CLI. Same dashboard." is true but understates: the differentiator is not "two providers in one window" (tmux does that trivially) — it is "two providers in one *triage queue* with one *anomaly detector*." The current caption sells real estate, not intelligence.
- **Act 2 overclaims "Kookr flags it instantly."** The narration asserts detection but the visual is just a row pulsing and jumping to the top of a queue — a styling choice tmux users will pattern-match to "a notification, like every other tool." There is no visible inference step. If you keep the "flags it" claim, the UI needs to render a one-line *reason* ("Bash permission prompt detected from hook event") so the AI/anomaly story is corroborated, not asserted.
- **Act 3 "AI suggests a response" with three pre-drafted replies is the riskiest beat for skeptics.** Three suggestions appear instantly, the cursor approves the first one. Nothing on screen proves the suggestions were generated, not hard-coded fixtures (which, in the demo, they literally are). At least one visible affordance — a small "generated by Claude Sonnet" stamp, or a fake 400ms loading shimmer — would buy credibility cheap.
- **"Anomaly detection" appears in the README ("Core Features") but never on-screen in the video.** A viewer comparing Kookr to `crewAI` sees a Trello-like queue and concludes Kookr is a kanban board for agents. The detection layer — the thing that differentiates Kookr from every framework that *runs* agents but does not *watch* them — is invisible.
- **Closing pills "Local-first. Multi-agent. Multi-project."** miss the headline word. "Supervisor" or "attention router" should be one of those three pills. "Multi-agent" alone is what `crewAI` says about itself.

### 5 specific edits to make the differentiation crisp

1. **Rewrite the Act 0 caption to name the automation, not the symptom.** Problem: the current line ("5 AI agents working. One needs you. Which one?") could be a tmux user's tweet. Target: `script.md` Act 0 caption (line 13) and `NARRATIONS.hook` in `rfc.md` (line 87). Proposed caption: **"5 agents running. Kookr already spotted the one that's stuck."** Proposed narration: "Five AI agents running in parallel. Kookr already spotted the one that's stuck — before you opened the tab." The verb "spotted" carries the detection claim that "needs you" omits; "before you opened the tab" implicitly attacks the tmux-eyeballs baseline.

2. **Add a one-line "why flagged" reason to the Act 2 permission card.** Problem: Act 2 narration says "Kookr flags it instantly" but the visual shows only a pulsing row, indistinguishable from a generic notification. Target: `script.md` Act 2 visual block (line 87–93) and the finding-card render in `demo/record.ts`. Proposed change: under the prompt text `Allow Bash: npm test --coverage?`, render a small grey subline: **"Detected via Claude Code hook (PreToolUse · Bash)."** This is true to how the detection actually works and visually corroborates the "flags it" claim — turning a tmux-shaped notification into a hook-driven inference no terminal multiplexer can do.

3. **Stamp the AI suggestions in Act 3 with a model badge and a brief shimmer.** Problem: three suggestions appear instantly, indistinguishable from canned fixtures. Target: `script.md` Act 3 visual block (line 117–127). Proposed change: when the suggestion panel slides in, show a 400ms shimmer placeholder for ~300ms before the three options render, and tag the panel header **"AI suggestions · Claude Sonnet · 0.3s"** (or whichever model is wired). The latency hint plus the model name is the cheapest possible "this is actually an inference, not a fixture" signal.

4. **Reframe the closing pills to put the differentiating noun first.** Problem: "Multi-agent. Multi-project. Local-first." overlaps semantically with `crewAI`'s tagline. Target: `script.md` Act 6 caption 1 (line 200), `NARRATIONS.closing` in `rfc.md` (line 105), and the closing-card pill list (line 212). Proposed pills: **`Attention router`** · **`Multi-runtime`** · **`Local-first`**. Proposed caption: **"Attention router for parallel agents. Multi-runtime. Local-first."** "Attention router" is the phrase the LinkedIn body already uses and is unowned in the competitive landscape — it is the only two-word phrase here that no competitor's homepage uses.

5. **Insert a 3-second "what Kookr sees" overlay during Act 1's Codex spotlight.** Problem: Act 1 currently demonstrates filtering and provider badges, both of which look like UI conveniences a sufficiently configured tmux setup could approximate. The script never visualises Kookr's actual sensor inputs (hook events, transcripts, GitHub state). Target: `rfc.md` "Codex CLI integration callout" §2 (line 67–72) — extend the existing `showProviderBadge()` overlay. Proposed overlay text replacing the current Codex tooltip body: **"Kookr watches: hooks · transcripts · terminal · GitHub PRs/CI · cost · per-project budgets."** This single line is the only place in the entire video where the *breadth* of the supervision surface is stated, and it does the work of separating Kookr from every framework, IDE, and terminal multiplexer in one beat. Keep the Codex fork reference on a second line; the overlay can hold both for 3 seconds.
