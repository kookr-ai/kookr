Kookr · RFC · Draft v2

Self-Improving Agent Fleet with Bounded, Measured Memory

A main orchestrator launches specialized sub-agents that act across repositories and capitalize their experience — while memory stays small, auto-purging, and earned by measurement rather than assumed.

2026-10-22 author Jean Ibarz (with Claude) reviewed by 5-role swarm + consensus attack + 2 critics reuse-first 1 playbook · 1 skill · 1 CLI verb

The idea in five lines

  • 1Two layers, never welded. Persistent cross-repo workers (the fleet) and ephemeral in-process lenses (the swarm) bound memory in opposite ways — keep them apart.
  • 2Memory is a measured liability. Standing semantic memory is default-off; an agent capitalizes mainly by promoting verified lessons to skills and re-deriving the rest from git/PRs.
  • 3Every write gets a down-step. Kookr already forces a lesson per task but never prunes — 1,319 notes and growing. We add the missing actuator.
  • 4Typed brief in, typed result by reference out. Workers return a pointer + verdict, not a conversation. An evaluator closes the loop — this is what cuts the back-and-forth.
  • 5Measure before you build. Phase 0 proves whether memory even helps, before any store machinery exists.

01Why this is not a greenfield build

Kookr already contains almost every part. The honest gap is narrow. Two facts frame the whole design.

Fact 1 — Kookr has two "agent" layers, and they bound memory oppositely

The request — "an orchestrator launches persistent cross-repo sub-agents with their own memory" — is Layer A. The "specialized lenses" (critics, reviewers) are Layer B. Collapsing them into one "sub-agent" abstraction is the single biggest design risk.

Fact 2 — the memory asymmetry is already shipped, and already hurting

Kookr forces memory up: the post-task gate (issue #1538) returns 409 on completion-ready unless a lesson was written. It has no down-step at all. The result is measured, not hypothetical.

02Eight principles the design commits to

These are the requirements. They encode the swarm's hard-won agreements and the two corrections the consensus attack and critics forced.

R1

Two layers, never welded

Persistent memory and the brief→artifact contract ride Layer A only. Layer B stays ephemeral.

R2

Memory is a measured liability

No standing semantic store by default. Capitalize via procedural skills + just-in-time re-derivation; switch semantic memory on per-scope only where measured to help.

R3

Every write has a down-step

For the forced-write gate, a prune/demote counterpart. The injected budget (~1–2K tokens) is a hard cap.

R4

Purge = demote, not delete

Hidden-but-retrievable, undoable by run id. The fleet's shelves are separate from the shared human/kb-scout commons; autonomous apply never touches the commons.

R5

Typed in, typed by reference out

A complete brief in; a small result pointing at an artifact out. Loops close with an evaluator, not a chat. Missing results are a defined state.

R6

Spawning is disciplined

A sub-agent ≈ 15× tokens. Spawn only when parallelizable AND verifiable AND worth it. No own memory or tool boundary → it's a prompt.

R7

Reuse over build

A playbook + skill + hook + one thin verb beats a new service — except where reuse is skin-deep (demote is a real cross-package change).

R8

Observable before/during/after

A wrongful demotion or budget breach is caught by a signal, not by its consequence. Dry-run, ledger, blast-radius cap, regret tripwires, metered cost.

03The system shape

One orchestrator applies the spawn rule, dispatches typed briefs, reads typed results by reference, and verifies worker claims. A scheduled janitor keeps memory bounded.

04The memory model — procedural-first, semantic default-off

The user's priority: capitalize experience and keep memory small and auto-purging. The reconciliation is that these live on different layers — you bound what gets injected, not what the fleet knows.

The load-bearing distinction

Decays-out-of-hot ≠ truly forgotten. Dropping below the injected top-k budget is invisible but recoverable (still on disk, still reachable by explicit search). A demotion is hidden-but-flagged and undoable by run id. Deleting a backing row is not a default operation at all.

The write is a reconciliation, not an append

When a scope's semantic memory is switched on, every candidate fact is reconciled against the nearest existing memories — the Mem0 four-operation pattern — and contradictions are time-stamped as invalid, never deleted (the Zep rule).

The Forgetter's catch — don't launder the leak

"Promote recurring lessons to a skill" sounds like the bounded answer, but it can just relocate the 1,319-note pile into an authoritative-looking skill library that nothing purges. So the procedural store is capped too, by a fitness score — how often a skill actually fires and succeeds — contingent on that telemetry existing.

05The one genuinely new piece — a prune actuator that demotes

The missing self-prune path. Composed from three proven in-repo loops — but two critic corrections mean it is not the thin verb v1 imagined.

Correction — two problems, never conflated

The commons problem (the 1,319 shared notes humans and kb-scout read) is real but is a propose-only, human-gated job — autonomous apply on the commons is forbidden. The fleet problem (new <capability>/<repo> shelves the fleet owns) is where apply can eventually run.

Correction — demote is a cross-package change, not a verb

"Demote while staying retrievable" needs the external KB package to gain a per-note index-exclusion state it does not have. So kb demote is a version-pinned prerequisite, shipped propose-first; --apply is gated on package support, a kb undemote --run=<id> restore verb, an enforced shelf allowlist, and a restore drill.

06The contract that cuts the back-and-forth

Workers have no shared memory, so the brief is the contract. The result returns a pointer, not a payload, and an evaluator — not a conversation — closes the loop.

BRIEF — in

Everything the worker needs

objective · repo_scope · cwd · output_format · acceptance (rubric) · allowed_tools · boundaries · artifact_path · memory_scope (absent by default) · brief_id.

RESULT — out

A pointer, not a payload

verdict (pass/block/input_required) · artifact_ref · review-head-sha · brief_id · cost_usd (cross-check only) · summary ≤2000 · started_at/last_progress_at so a hung worker is a state, not silence.

07Delivery — measurement before machinery

The decisive point from the consensus attack: the benefit of standing semantic memory was never measured, and the one in-house measurement is negative. So we build the measurement first, and every later phase is conditional on it.

  1. Measure (a designed experiment)

    Per-chunk injection logging with an injected | suppressed | off tag; a randomized injection-off holdout (observational on/off is confounded); outcome join via the terminal-task archive; a report surface (per-scope outcome on-vs-off, with a minimum-n). Plus a 3-state fail-closed flag on the one unconservative branch, default log.

    depends on: nothing · creates the population the opt-in hook otherwise lacks

  2. Typed contract + spawn rule

    The brief/result grammar as a doc, then its first real slice — a parser that consumes it; the Spawn-Decision Rule + effort ladder; a server-side metered fleet cost roll-up. Keep the hook-JSONL path as a cross-check; don't retire the sweeps yet.

    depends on: nothing

  3. Self-prune actuator — propose only

    The janitor skill + schedule in propose-only mode; dry-run diff; per-note manifest; blast-radius cap. Surfaces the commons defect for human review.

    depends on: P0 (outcome signal) + P1 (cost ceiling for the scheduled job)

  4. Apply — fleet shelves only

    kb demote --apply + kb undemote, gated on external-package support, shelf allowlist, restore drill, quarantine period. Never on the commons.

    depends on: P2 + external-package capability

  5. Earn semantic memory + fitness cap

    Turn on fleet semantic shelves only where P0 shows benefit; Mem0 four-op writes; promote ≥2-repo lessons to skills; fitness-cap the skill library (if telemetry exists).

    depends on: P0 data + P2a

The honesty test

P0, P1, and P2 are worth doing even if P3 never happens — even if the honest answer turns out to be "no standing semantic memory." P0 is the measurement, P1 is the contract, P2 surfaces the leak for review. Only P2a and P3 depend on the store being worth keeping. A design that survives its own premise being false is a design that respected the attack rather than rationalizing past it.

08Seeing what the night did

Both critics found the same gap: an autonomous demotion and a lights-out cost integral must be caught by a signal, not by "later tasks score worse" or an invoice. Everything here reuses an existing Kookr surface.

LEDGER

Per-note manifest, mandatory

Every run writes path, hash, classification, score inputs, archive path to audit.jsonl. No audit row → no apply.

BLAST RADIUS

Abort a runaway classifier

If > ~10% of a shelf would be demoted in one run, abort and escalate. The cheapest guard there is.

REGRET

Tripwires, not outcome drift

Log every explicit search that hits a demoted note, and every kb remember that re-learns one. A rising "regret rate" is the alarm.

RECOVERY

Undo by run id

kb undemote --run=<id> ships with apply; a quarantine period keeps a demotion reversible while tripwires watch.

COST

Metered, server-side, live

Authoritative cost comes from adapter metering keyed by brief_id — not worker self-report (a crashed worker reports nothing). Exposed in orchestration status.

BREACH

A cost-ceiling pause

50/80% soft thresholds feed the anomaly detector; the hard stop refuses new spawns and leaves a visible reason.

09How this RFC was built

Not by one voice. Five invented, deliberately-conflicting agents brainstormed it blind and in parallel; a devil's advocate attacked their agreement; two critics hardened the result against source.

bounds ⟷ capitalizes

The Forgetter

Minimal memory, aggressive purge. Caught that promoting to skills just relocates the leak.

capitalizes ⟷ bounds

The Archivist

Never lose a hard-won lesson. Reframed the one negative datapoint: "inject less," not "store less."

cost ⟷ specialization

The Economist

Multi-agent ≈ 15× tokens. Gave the spawn rule and the typed, by-reference contract.

specialization ⟷ cost

The Fleet Maximalist

Many narrow specialists. Showed specialization is itself a bounding strategy; gave the worth-a-specialist test.

reuse everything

The Dark-Factory Mechanic

Build nothing bespoke. Mapped every capability to an existing mechanism; flagged the Layer-A/B welding risk.

attacks the consensus

Devil's advocate

Found the shared blind spot: the whole panel assumed a semantic store should exist. It reframed the RFC's thesis.

Then delivery-pragmatist and operability-reviewer checked the draft against the real code — and corrected it: the "fail-open leak" wasn't visible in the actual opt-in hook; the janitor had been scoped to empty shelves; kb demote was a cross-package change; and the autonomous path needed the whole observability layer in §08. Every load-bearing reuse claim was verified against source.

10Open questions

  1. Retrieval-outcome attribution. Crediting one of 5–20 chunks for a task's success is unsolved; P0 starts with the coarse randomized signal, not per-chunk attribution.
  2. External package as mutation infra. kb demote/undemote live in a separately-versioned package; pin it, keep apply human-gated behind a contract test, and run a restore drill first.
  3. Commons ownership & migration. Who owns the shared shelves, and how are the ~1,300 frontmatter-less legacy notes handled — left out of scope, or a human-gated tagging migration?
  4. Skill-fitness telemetry. Low-fitness skill demotion needs a per-task skill-firing + outcome signal that does not exist yet; defer the fitness cap until it does.
  5. Concurrency default. Start at 4 or 20? Resolve with P1's metered-cost evidence from a real lights-out run.
