Kookr · interface review

The layout is sound. The screen carries too much.

Kookr exists to tell you which agent needs you next. The dashboard still has the right bones: it descends from spike proposal 33, “Supervisor-First Triage”. What hurts is that each feature since has added a pill, a banner or a button at the same visual weight as everything else, and the rail reserves its largest area for agents in trouble even when there are none.

Recommendation

Build variant B, the triage inbox, in five steps. The first three are worth shipping whichever layout you choose and get most of the way to variant A.

Where it stands

Today, with nothing needing you

This is how the app looked when I measured it: eight agents running and none waiting on you. The numbered pins match the notes underneath.

  1. 1

    A permanent red banner

    “Permissions bypassed” is a mode you chose. It runs full width on every screen and repeats as a two-line badge in the task header, so red stops meaning “look now”.

  2. 2

    Twelve top-bar controls at one weight

    The build hash sits in a bordered box beside the logo, all-time spend is set in warning amber, and four icon buttons have no visible label.

  3. 3

    52 project icons, 3 with a task

    The same two-letter initials appear two or three times, so tiles are hard to tell apart. The column scrolls for about 2,300 px.

  4. 4

    The most destructive action is the most visible

    “Abort all” sits in the rail header in red at all times and squeezes the header title down to “SUPE…”.

  5. 5

    The rail reserves space for trouble

    With no findings, 502 px stay empty while eight running tasks share 255 px. Two fit. The overview pane then lists the same tasks a second time.

  6. 6

    Titles are prompts

    Running tasks carry the first line of their prompt, so most start with “You are” or “Your job is”. Each card also spends a row on six small icon buttons.

  7. 7

    Seven header actions, six styles, no primary

    ID, Link, Share, Details, Complete, Reflect and Cancel sit side by side. Nothing says which one you usually want.

  8. 8

    The conversation starts 300 px down

    A “Relationships: none” row and a four-row timestamp card come first. The terminal beside it replays the same session at half width.

  9. 9

    Eleven status readouts at one weight

    Counts, spend, CPU, RAM, two quotas, watchdog, schedules and speech. At 1180 px the bar wraps to two lines and the floating agent pill covers part of it.

Underneath, the stylesheet has grown without a scale: 33 declared font sizes, 99 hex colors and 274 distinct rgba values against 19 tokens, 23 corner radii, and 41 button, 50 pill, 39 banner and 60 badge class names. The muted text color is used 302 times and reaches only 3.3 to 3.8:1 contrast, below the 4.5:1 minimum for small text.

Foundation

Seven rules every variant shares

These fix most of what feels wrong and need no layout change. All four variants below are drawn with them.

RuleTodayProposed
Type scale
33 sizes declared, down to 7 px on screen
Five sizes: 12, 13, 14, 16, 20. Nothing under 12. Monospace only for commands, IDs and money.
Contrast
Muted text at 3.3 to 3.8:1
Three text tiers, each at 4.5:1 or better on the surfaces it sits on.
State color
Teal, green, blue, amber and red all mark state; red also marks a mode
Amber means waiting on you. Red means failed or stuck. Teal means selected or the main action. Everything else is neutral, and each state also has its own shape.
Actions
Up to seven peers per surface
One main action per surface, the rest in a menu. Destructive actions never sit on screen at rest.
Names
First line of the prompt when the namer falls back
A short task name always. The fallback strips openers such as “You are” and “Your job is”; the full prompt stays one click away.
Chrome
Banner, 12 top-bar controls, 11 status readouts
A quiet mode chip, one System indicator that opens the detail, build info under About.
Empty states

Variants

Four ways to restructure the screen

Same twelve tasks in every frame. Switch between a moment when three agents are waiting and a quiet one, and click any task to open it.

Recommendation

Build B, and get there through A

B is the only variant that fixes all three structural problems at once: projects become readable names, the list fills the rail in every state, and the task pane leads with what the agent is asking and the buttons to answer it. It also removes the most chrome, because usage and quota move into the navigation and the status bar goes away.

A is the safer half of the same work. It keeps the icon rail and the side-by-side terminal, so it changes less and tests survive, but projects stay cryptic and the conversation stays narrow.

C works as a second view of the same tasks for a large monitor, added later behind a Board and List switch. I would not make it the main layout: long conversations do not fit a side sheet. D is the weakest fit. It hides the fleet, and moving you between tasks automatically is what dogfooding finding F17 already flagged as disorienting.

None of these directions is new to the repository. docs/spikes/gui-proposals holds a kanban (21), focus modes (12 to 15, 26) and a three-column layout (27) from before proposal 33 was picked. What changed since is the load: 52 projects, 41 schedules, costs, quotas and pull requests that proposal 33 never had to hold.

  1. Tokens and contrast. The type scale, one spacing scale, three radii, the three text tiers and the four state colors. No layout change, so it ships as a pure visual diff.
  2. Quiet chrome. Banner to mode chip. Status bar down to counts, spend and quota, with the rest behind System. Build hash to About. “Abort all” into a menu with a confirmation.
  3. One list. Merge Findings, Healthy and Completed into a single list grouped by state, with compact rows. Find out why task naming falls back to the prompt on your instance, and make the fallback strip openers.
  4. Reading pane. One meta line, one main action, the decision card, the facts column. Terminal becomes a tab, with a split toggle for wide screens.
  5. Labelled navigation. Queues and named projects replace the icon rail and collapse to icons on narrow windows.

Test impact to plan for: the e2e folder (55 spec files plus helpers) references .finding-card 218 times, .healthy-row 61 times and .statusbar 42 times. Step 1 leaves those alone, step 2 touches the status bar, and step 3 can keep the old class names on the new rows.
